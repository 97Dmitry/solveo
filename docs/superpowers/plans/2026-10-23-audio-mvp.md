# Audio MVP: local STT in the app — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** In Solveo, one button prepares local speech recognition (builds the `solveo-stt` Docker image, downloads Qwen3-ASR), a status shows readiness, and during an interview the transcript of system audio and the microphone can be sent to the LLM or inserted into the composer.

**Architecture:** Windows Solveo.exe captures system loopback and the default microphone through WASAPI (narrow COM bindings) and streams native-format PCM over an authenticated localhost WebSocket to a self-owned Linux container. The container runs a Python worker built from sources embedded in the exe: Silero VAD + Qwen3-ASR streaming partials + hybrid offline final. Go owns setup/status, the in-memory transcript and submission through the existing chat pipeline.

**Tech Stack:** Go 1.27.1, Wails v2, `golang.org/x/sys/windows` + `github.com/go-ole/go-ole` v1.3.0 (already in go.sum), `github.com/coder/websocket` v1.8.15; Python 3.12 in `vllm/vllm-openai:v0.14.0@sha256:1d6866b87630d94f5e0cdae55ab5abb4ce0b03fcb84d9d10612f9d518d19d4fd`, qwen-asr 0.0.6, `silero-vad==6.2.3`, `websockets` (latest release at least two weeks old at implementation time, pinned in the lock); React/TypeScript/Zod via Vite+ and pnpm.

**Spec:** [local audio plan](2026-10-22-local-audio.md) with its «Решения 9.0», [evaluation report](../../roadmap/2026-10-22-local-stt-evaluation.md), [design §9.2](../../specs/solveo-design.md). User decisions of 2026-10-23 override the earlier plan where they conflict:

1. Stage 9.0 is shortened: acceptance is a live mock interview from YouTube instead of a full corpus/holdout.
2. Sources: system audio **and** microphone in the first version.
3. Transcript → LLM: selected final phrases are either sent immediately (**Отправить**) or appended to the composer (**В поле ввода**). No separate durable question card.
4. The model is loaded by an explicit **Запустить модель** button and unloaded by **Выгрузить**; listening starts only from a ready model.
5. **Подготовить** builds the image named `solveo-stt` and downloads the model; a status shows whether everything is ready.

## Global Constraints

- Model `Qwen/Qwen3-ASR-1.7B@7278e1e70fe206f11671096ffdd38061171dd6e5`, BF16, vLLM kwargs: `dtype="bfloat16"`, `gpu_memory_utilization=0.6`, `max_model_len=2048`, `max_num_seqs=2`, `max_num_batched_tokens=2048`, `limit_mm_per_prompt={"audio": 1}`; SamplingParams temperature 0, 32 tokens per streaming step, 256 for the offline final; chunk 1.0 s; `unfixed_chunk_num=2`, `unfixed_token_num=5`; language `None` (auto).
- Hybrid final: one offline `transcribe()` over the whole utterance PCM (pre-roll included); `finish_streaming_transcribe` is never called. A streaming step that hits the 32-token cap stalls partials for that utterance; the final still comes from the offline pass.
- VAD: Silero, 16 kHz, 512-sample windows, threshold 0.5, endpoint silence 800 ms, pre-roll 300 ms; max utterance 20 s → forced final, a new utterance continues.
- Context: `"Technical interview in Russian with English IT terms. Write these terms exactly as listed when they are spoken:\n"` + phrases joined by `"\n"`; empty dictionary → empty context; total ≤ 4096 bytes UTF-8 (worker rejects larger with an error, never truncates).
- Worker must verify `"Qwen3ASRForConditionalGeneration" in ModelRegistry.get_supported_archs()` after importing qwen_asr, set `HOME=/tmp` and `USER=stt`, warm up on 2.5 s of zeros before reporting ready, and never download anything at serve time (`HF_HUB_OFFLINE=1`).
- Docker: only a local engine (`DOCKER_HOST` unset and context endpoint `npipe://` or `unix://`); container name `solveo-stt`, label `solveo.component=stt`; port published only on `127.0.0.1`; random 32-byte hex token per start; `--gpus all --shm-size 2g --memory 12g`; model mounted read-only from `solveo-data/models/Qwen3-ASR-1.7B-7278e1e`. Solveo removes only a container that carries its label and never touches other containers.
- Lease: the worker exits 30 s after its last WebSocket session closes (or 30 s after ready with no session); Go stops the container on Exit.
- Raw audio stays in RAM; no WAV files. Transcript is RAM-only, lost on restart; at most 300 segments (oldest evicted).
- Nothing is sent to the LLM without an explicit click; Отправить never attaches queued PNGs and never reads or changes the composer draft.
- Go error texts shown in the UI are Russian. Times in Go are UTC (`chat.Now()`).
- New modules get `AGENTS.md` + `CLAUDE.md` (`@AGENTS.md`). Tests never call real Docker, GPU, model or LLM.

## Review Focus

1. Loopback delivers no packets while nothing plays: the worker must still see continuous time so the VAD can end the utterance — capture fills gaps with zeros (Task 5 `TestSilenceFillerCoversPacketGaps`).
2. A phrase is still being recognized when the user clicks Отправить: only final segments are accepted; partial segment IDs are rejected (Task 6 `TestSubmitTranscriptRejectsPartial`).
3. The worker dies or the container is killed while listening: capture stops, status shows the error, chat stays usable, nothing restarts automatically (Task 6 `TestWorkerLossStopsListening`).
4. Inference falls behind (two simultaneous speakers): partials are coalesced into one decode instead of growing latency; finals are never dropped (Task 1 `TestStreamingStepsCoalesceBacklog`, `TestFinalHasPriorityOverSteps`).
5. Prepare is clicked twice or during start: one long operation at a time; a second request returns «Подготовка уже идёт» (Task 6 `TestAudioOperationsAreExclusive`).

## Rulings against the earlier stage plan

- Native PCM goes to the worker and is resampled there with soxr: no hand-written DSP in Go (earlier plan resampled in Go).
- No durable question card, `AudioOrigin` provenance or crash reconciliation: Отправить creates an ordinary user turn; В поле ввода uses the existing draft (user decision 3).
- Listening is not bound to a chat and is not stopped by switching chats; sending targets the active chat.
- Default devices only; device choice, tray recording indicator and Docker image digest pinning of the built image are deferred.
- Lease is "exit 30 s after the last session" instead of a heartbeat protocol; the WebSocket session itself is the heartbeat.

## Уточнение контекста Qwen (2026-10-23)

Текущая инструкция остаётся прежней, но при окончательном offline-проходе строки выбранных терминов могут дополняться фонетическими подсказками из `solveo_stt/pronunciations.json`. Канонические названия не теряются; необязательные подсказки добавляются в пределах оставшегося бюджета 4096 байт. Пустой словарь по-прежнему даёт пустой context. Это уточняет правило context в Global Constraints, не меняет модель, язык или sampling. Основание: [план качества](2026-10-23-qwen-quality.md) и [измерения](../../roadmap/2026-10-22-local-stt-evaluation.md), раздел «Продолжение: качество Qwen».
Промежуточные streaming-состояния используют прежний канонический context без фонетических подсказок.
