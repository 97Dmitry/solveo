# Прикрепление окна аудио слева

Согласованный сценарий: кнопка переключает плавающее окно аудио и внешнее
прикрепление слева. Чат не становится уже. В dock-режиме окно следует за
позицией и высотой основного; ширину аудио сохраняем. Открепление оставляет
окно на текущем месте. Режим хранится только в текущем дочернем renderer.

Нельзя использовать SetParent/owner между потоками/процессами Wails.
Сохраняем два независимых capture-excluded окна. Config через stdin дополнится
HWND/PID родителя только для чтения его геометрии. Дочерний renderer применяет
координаты только к своему окну через SWP_ASYNCWINDOWPOS (доставка оконному потоку Wails; без
синхронного межпоточного SetWindowPos). UI-команды dock/float
обрабатываются локально, не доходят до STT/controller. Здоровье родителя и
show_version по-прежнему контролируются независимо от JS timers.

Если слева нет свободного места — attach отклоняется с пояснением. Если места
не стало во время движения — автоматическое открепление без потери окна за
краем экрана. При скрытии/минимизации основного прикреплённое аудио скрывается;
при восстановлении появляется, только если его скрыл сам dock-механизм.
Закрытие крестиком не должно приводить к автоматическому повторному показу.
В плавающем режиме связь видимости с основным отсутствует.

Проверки: pure geometry и visibility state machine, кнопки UI и ошибки,
make check, race и Windows cross-build. Реальное перемещение, DPI/мониторы,
фокус, скрытие/восстановление и capture exclusion — отдельная Windows-приёмка.


Выполнено: кнопка dock/float, локальные callbacks без controller/STT,
следование в физических координатах с периодом 33 мс и без активации окна,
автоматическое открепление при нехватке рабочей области. Плавающий режим
оставляет последнее положение; постоянная настройка режима не добавлялась.

Ревью выявило, что Wails HideWindowOnClose обходит OnBeforeClose. Исправлено:
HideWindowOnClose=false, пользовательский close обрабатывается ClosePolicy
как manualHide, а явный parent-loss exit помечается BeginQuit. Pure regression
сначала FAIL, затем PASS. Ревью исправления — без новых замечаний.

Проверено: make check PASS (91 frontend tests, 40 worker tests, Go suite,
host/Windows lint, Windows vet, Solveo.exe); go test -race ./internal/audiowindow
PASS; go test -race -tags bindings . PASS; root cross-compile с -tags dev PASS.
Фактическое native перемещение и DPI не проверены; manual acceptance остаётся
отдельно в docs/windows-acceptance.md. Минимизированный HWND не используется
как источник ширины: renderer сначала восстанавливается, затем выравнивается.
