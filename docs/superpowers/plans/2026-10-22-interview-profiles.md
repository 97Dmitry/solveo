# Профили подготовки интервью — технический план

**Goal:** реализовать шаг 4 roadmap: сохраняемые профили подготовки и независимые чаты из них.
**Architecture:** профиль хранит копию расширенного `chat.Config`; Go владеет библиотекой, ревизиями и атомарной записью, React редактирует форму и вызывает Wails-команды. Существующие Submit, история и подготовка Codex остаются общими путями.
**Tech Stack:** существующие Go/Wails/React/Zod/Vite+, без новых зависимостей.
**Spec:** [описание поведения](../specs/2026-10-22-interview-profiles-design.md), раздел 4 [roadmap](../../roadmap/2026-10-21-core-features.md).

Статус: реализация завершена. По запросу пользователя подготовлена к публикации в ветке `feat/interview-profiles`, база `master` (`7a4e4ae`).

Проверка описания отдельным агентом: существенных открытых вопросов не найдено.
Проверены хранение полей в Config/RequestConfig и совместимость с PrepareChat
без turn/start. Это проверка проекта решения, а не тестирование реализации.

## Ограничения

Текущий checkout; без commit/push/PR. Сохранять совместимость старых архивов и
RequestConfig. Общие инструкции копируются только при создании чата, не из
профиля. Все тесты используют fake provider/CLI. Правила хранения, лимиты и
подтверждения — из описания поведения. Никаких прямых изменений пользовательских
хранилищ: новое поведение реализуется и проверяется через код и временные файлы.

## Основные риски и проверки

1. Изменение профиля после создания чата: конфигурация, globals и retry исходного чата остаются прежними.
2. Испорченный/новый файл, symlink escape и отказ записи: библиотека не затирается, чат остаётся рабочим.
3. Устаревшие revision/ID и повторные клики: отклонение без частичной записи и переключения чата.
4. Несохранённая форма и недоступная модель: нет потери текста и молчаливой замены значений.
5. Опыт пустой или содержит вставленный текст: нет дополнения шаблонными фактами, поле доходит до обоих запросов без превращения в сообщение пользователя.

## Результат и отклонения

- PR #11 (этапы 2.2 и 3) слит по явному разрешению пользователя; checkout переключён на `master`, база `7a4e4ae`.
- Профили реализованы без новых зависимостей. Config включает поля позиции, стека, формата и реального опыта; профиль не содержит globals, сообщений, снимков или provider state.
- В wire используется `ProfileView` с UTC-строками, на диске `Profile` с `time.Time`. ProfilesStore подключён в Windows entrypoint; его отсутствие в существующих test/embedded consumers явно отключает библиотеку, не изображая успешное сохранение.
- Диалоги подтверждения выполнены внутри существующей панели через Button. Библиотека доступна при `can_switch`, включая read-only архивы; применение преднастройки остаётся под `can_edit_config`.
- Валидацию старых архивов не ужесточали. Совместимость, отдельные snapshots чатов, сохранение полей в архиве и frozen retry проверены через общий путь контроллера.
- `.gitattributes` отключает проверку пробелов в конце строк только для generated Wails bindings: генератор оставляет табы на пустых строках, файлы сохраняются как сгенерированы.
- Независимое ревью нашло один P2: вход в панель из read-only чата оставался заблокирован. Исправлено с RED→GREEN UI-тестом. Других обоснованных findings не получено.
- Дополнительный RED→GREEN закрепил ревизию выбранного профиля до редактирования: новый snapshot не позволяет затереть более свежую версию. После обновления собственная успешная ревизия продвигается явно.
- Исправлена недетерминированность теста параллельного retry: исходный общий канал случайно распределял ошибку между подходом и решением. Теперь используются отдельные каналы существующего parallelProvider; 10 повторов под race detector прошли.

## Упрощение выбора профиля по пользовательской проверке

По запросу пользователя отдельная кнопка «Загрузить в форму» удалена.
Выбор в select сразу заполняет поля. Ручные изменения защищены подтверждением;
при отмене сохраняются текст и прежний профиль/имя/ревизия. Baseline формы
обновляется при загрузке профиля, поэтому переключение неизменённых профилей
не требует лишних кликов. Имя чата не заменяется; его несохранённая правка
защищается отдельно при создании нового чата. Сохранение преднастройки
остаётся явным действием без генерации ответа.

Регрессионные тесты: автоматическое заполнение, последовательное переключение,
отмена замены, отдельное SaveChatConfig, каталог и сохранность ревизий,
неизменность имени чата и подтверждение навигации с его правкой.

После упрощения выбора `make check` пройден: 50 frontend-тестов, форматирование,
lint/types, Go tests, host/Windows lint, Windows vet и пересборка
`build/bin/Solveo.exe`. `git diff --check` пройден. Нативная проверка нового
выбора профиля остаётся отдельной; новые зависимости не добавлялись.
