# Qwen: качество смешанной RU/EN речи и терминов

Цель: улучшить окончательный текст существующего Qwen-провайдера по запросу пользователя. Основной критерий — английские IT-термины в русских фразах; сохранять числа, отрицания и пустой результат на тишине. Архитектура — `docs/specs/solveo-design.md`, текущий audio MVP; исходные измерения — `docs/roadmap/2026-10-22-local-stt-evaluation.md`.

Ограничения: та же BF16-модель и revision, vLLM 0.14.0, auto language, память 0.6, hybrid final. Не заменять распознавание догадками LLM/нечёткими автозаменами. Не менять эталоны и разметку после просмотра результата. Ранее добавленные облачные адаптеры сохранить; новые облачные запросы не нужны.

1. Сверить реализацию и известные ошибки. Повторный forcing Russian и context без инструкции не нужен: они уже проверены и отклонены.
2. На локальном dev-корпусе сравнить свежий baseline с двумя ограниченными альтернативами context: русская инструкция с исходным словарём и явная инструкция сохранять английское написание без перевода. Одна загрузка модели, одинаковые аудио/словарь/декодирование, финальный offline-проход, включая тишину и шум. Это dev-эксперимент, не независимый holdout и не измерение live-задержки.
3. Выбирать по точности терминов при отсутствии ухудшения критичных фрагментов/тишины; WER — дополнительный контроль. Успешный вариант повторить вместе с baseline. Если выигрыш не подтверждён, настройки production не менять и зафиксировать отрицательный результат.
4. Только при подтверждённом выигрыше обновить production context, синхронизировать benchmark template, добавить проверку контракта и обновить инструкции/отчёт. Сохранить пустой словарь → пустой context и лимит 4096 байт.
5. Проверки после изменения: worker fake tests, `make audio-bench-test`, `go test -race ./internal/stt/...`, `make check`. GPU-прогон дополняет unit tests, Windows live-захват требует отдельной приёмки.

Открытые ограничения: 30 записей одного говорящего; часть первых слогов, вероятно, обрезана; 20-секундные фразы и реальные собеседники хуже представлены. Нельзя объявлять качество улучшенным по одному удачному примеру.

## Ход проверки

- Реализация и предыдущие замеры сверены. Подготовлен воспроизводимый GPU-скрипт `tools/audio-bench/corpus/results/qwen-quality-2026-10-23/probe.py` (локальный игнорируемый каталог корпуса): три шаблона, по два повтора, исходная разметка и SHA256 manifest, одна загрузка модели.
- Первый полноценный старт прервался до распознавания: `Available KV cache memory: -1.67 GiB`, `No available memory for the cache blocks`. Параллельно появился работающий контейнер `solveo-stt`; после остановки измерительного контейнера он остался работать, VRAM занята примерно на 5.7 GiB. Чужой/пользовательский контейнер не останавливался. Для повторного измерения требуется выгрузить модель в Solveo.
- Ни один вариант context пока не проверен на аудио; production-настройки Qwen не изменены.
- Пользователь подтвердил Windows runtime: приложение скачало модель, запустило её в Docker; после остановки контейнер удалился. Это подтверждает запуск/остановку, но не качество live-захвата. GPU освободилась (около 6.6 GiB), измерение перезапущено без изменения параметров.

### Первый результат и уточнение эксперимента

Три контекста проверены дважды: baseline 50/63 термина, mixed WER 14.83%, критичные 10/12; русский 51/63, 15.17%, 10/12; усиленное английское написание 49/63, 25.17%, 8/12. На тишине/шуме 0/2 галлюцинаций везде. Русский контекст добавляет повтор в конце длинной фразы, английский переводит отдельные русские фразы и пропускает q11. Оба отклонены, production не меняется.

Дополнительный ограниченный dev-эксперимент: фонетические подсказки для канонических терминов (например, goroutine — «горутина») в context. Разметка/эталоны прежние. Сравнение baseline / phonetic / phonetic / baseline, без текстовых автозамен. Проверяются прежние критерии; одного прироста по терминам недостаточно при новых пропусках/переводах/повторах.

### Проверка токенизатора

Фонетические подсказки дали в обоих повторах 52/63 термина, mixed WER 13.79%, 10/12 критичных мест, тишина/шум без галлюцинаций; baseline в обоих повторах — 50/63, 14.83%, 10/12.

Обнаружено ранее указанное в отчёте расхождение токенизаторов: в Transformers 4.57.6 `fix_mistral_regex=False/True` даёт разные token IDs для 10 из 72 проверенных строк (42 термина + 30 эталонов), включая PostgreSQL, QueryBuilder, localStorage, GraphQL. Новый ограниченный эксперимент сравнит тот же baseline/phonetic на токенизаторе, сохранённом через AutoTokenizer с fix_mistral_regex=True во временный каталог. Веса и оригинальные файлы модели не меняются. Не переносить это изменение в production без проверки результата.

### Выбор реализации

Применить только подтверждённые фонетические подсказки, без изменения tokenizer: фиксированная таблица JSON рядом с worker, read-only data в образе. Дополнять лишь выбранные термины; исходное написание/порядок/полнота словаря сохраняются. Если контекст близок к 4096 байтам, пропускать только необязательные подсказки. Добавить JSON в Go embed/image hash. Benchmark получает явный `--pronunciations` и записывает SHA256, без дублирования таблицы; тест проверяет идентичность context worker и runner. Завершить повтором с streaming + hybrid final, unit/race/check и Windows EXE.

### Разделение контекстов после streaming-проверки

Подсказки в обоих режимах улучшили hybrid final 50→52/63, но ухудшили streaming 48→46/63. Поэтому `Track` получает отдельный `partial_context` (канонический словарь), а основной `context` остаётся обогащённым для final. `run_qwen --pronunciations` воспроизводит именно это: `RunConfig.final_context`, отдельный hash финального context. Fake tests проверяют маршрутизацию контекста; завершающий GPU replay — baseline против подсказок только в final.

## Завершено

- Выбранный режим подтверждён GPU replay: final 52/63 против 50/63, mixed WER 13.79% против 14.83%, streaming сохраняет 48/63; критичные 10/12 и тишина/шум 0/2 без ухудшения.
- Подсказки подключены только к final; канонический словарь полностью сохраняется, лимит контекста и пустой словарь покрыты тестами. JSON включён в embed и image hash.
- 40 worker tests, 54 benchmark tests, STT race tests и make check прошли; новый EXE собран. Итоговый GPU-контейнер завершился и удалён.
- Ограничение: небольшой прирост на dev-корпусе одного говорящего; Windows live и holdout не проверены. Словарь в настройках по-прежнему должен содержать нужные канонические термины.
