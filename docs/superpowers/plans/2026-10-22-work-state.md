# Этап 2: сохранность незавершённой работы — технический план

Дата: 2026-10-22. Ветка `feat/work-state` от `master` (`743d846`, PR #8).
Roadmap: [этап 2](../../roadmap/2026-10-21-core-features.md#2-сохранность-незавершённой-работы).

## Исходное состояние

- Черновики и очередь живут только в `Controller.drafts`/`queues`.
- PNG очереди пишутся в `os.MkdirTemp` и удаляются при выходе; `capture.SaveRegion`
  пишет сразу в итоговый файл без `Sync`.
- Превью потока есть только в памяти; `history.Load` помечает ход `interrupted` без текста.
- `DeleteChat` удалял черновик, но не очередь удалённого чата.

## Решения

- Новый пакет `internal/workstate`, данные в `solveo-data/work/`:
  `state.json` (version 1: по чатам черновик с ревизией, упорядоченная очередь,
  метка отправленной ревизии), `stream.json` (контрольные копии превью),
  `queue/<id>.png`. Один `state.json`: межчатовые переходы (перенос очереди при
  отбрасывании, удаление) — одна атомарная замена; хранятся только чаты с
  непустой работой.
- Запись — один писатель на файл, всегда текущее состояние из памяти
  (latest wins): запоздалая запись не может вернуть более старое состояние.
  Черновик накапливается 300 мс, превью — 1 с. Изменения очереди сохраняются
  синхронно до удаления файлов и сразу после захвата.
- Захват пишет во временный файл в `work/queue`, затем `Sync` и rename.
- Метка `submitted{message_id, revision}`: если после сбоя ревизия черновика
  совпадает с отправленной и вопрос есть в архиве, черновик очищается —
  текст не дублируется. Если пользователь продолжил печатать, черновик сохраняется.
- Сверка при запуске: записи очереди без PNG убираются с уведомлением,
  неучтённые PNG и временные файлы удаляются; работа отсутствующего в архиве
  чата с содержимым переносится в новый чат (случай отбрасывания при сбое архива),
  пустая — удаляется. Неподдерживаемая версия или нечитаемый файл — работа
  только в памяти без перезаписи; повреждённый JSON откладывается в
  `state.json.bad-<время>`.
- Частичный ответ только показывается у прерванной попытки с пометкой; он не
  попадает в архив, историю запросов и контекст LLM, исчезает после повтора.
  Автоматической отправки нет.
- Ошибки записи — постоянное `work_error` в снимке; данные остаются в памяти,
  запись повторяется.

## Допустимая потеря при аварийном завершении

Черновик — до ~0,5 с ввода (120 мс фронтенда + 300 мс + запись), превью —
до ~1 с потока + запись. Время записи пишется в лог строкой
`Solveo timing: work_save_ms` без содержимого.

## Вне этапа

Получение ответа из rollout Codex (`thread/read`) после сбоя; дубль прерванного
вопроса в контексте thread при повторе (существующее поведение).

## Проверки

Go с `-race`: «отправил → пишу → перезапуск», «отправил без ввода → перезапуск»,
ошибка диска и восстановление, удаление вложения во время записи,
`RetrySave`, повреждённый/будущий `state.json`, сбой между захватом и записью,
превью после сбоя и его отсутствие в контексте, `DiscardUnsaved`/`DeleteChat`.
Фронтенд: схемы, отображение восстановленного текста. `make check`.
Windows: [приёмка](../../windows-acceptance.md) с `taskkill /F`.

## Исправления после ревью (2026-10-22)

- [x] Операции очереди относительно `os.Root(work)`; отказ при ссылке на очередь.
- [x] Проверка версии JSON до декодирования структуры v1.
- [x] Ошибки доступа к PNG отличаются от отсутствия; при ошибке запуска исходное
  состояние защищено от перезаписи и очистки до восстановления доступа и перезапуска.
- [x] Ошибка финальной записи отменяет обычный выход, сохраняя память и повтор записи.
- [x] Метка отправки записывается до архива и LLM, чтобы быстрый ответ не возвращал
  отправленный текст в черновик. При ошибке записи вопрос остаётся неотправленным.
- Регрессионные тесты проверяют очистку через ссылку, несовместимую будущую схему,
  временно недоступную очередь, повтор выхода после ошибки диска и быстрый ответ.

- [x] Финальное независимое ревью: фоновые записи приостановлены до завершения
  `New`; восстановление сохраняет `dirty`, но не публикует неинициализированный снимок.
