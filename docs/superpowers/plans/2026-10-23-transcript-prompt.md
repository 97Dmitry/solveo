# Контекст транскрипции в LLM-запросе

Проблема: модель получает распознанную речь как обычный текст и не знает о
сленге, оговорках, нечётком произношении и возможных ошибках STT.

Решение: необязательный Message.FromTranscript (JSON from_transcript),
устанавливаемый только SubmitTranscript. Сохраняется вместе с вопросом,
клонируется и повторяется существующим путём. Старые сообщения имеют false.
Codex добавляет инструкцию текущего хода для обоих форматов ответа, только
при этом признаке; стабильные инструкции и их hash не меняются.

Инструкция: интерпретировать сленг и неоднозначное произношение по контексту,
не критиковать речь, отвечать на вопрос; не менять молча отрицания, числа,
ограничения и технически значимые условия. Существенное сомнение обозначить
или уточнить. Исходный транскрипт в истории не переписывать.

- [x] Регрессии: метка на запросе из транскрипта, сохранение через JSON,
  инструкция в ordinary/approach/solution, отсутствие в ручном тексте.
- [x] Реализация метки и prompt, инструкции модулей.
- [x] Go race, make check и новая сборка. Проверки fake-only.

Ограничение: вставленный в редактор и вручную отправленный текст остаётся
обычным сообщением; происхождение смешанного черновика не угадывается.
Никаких изменений старых архивов, настроек или автоматических запросов.

Проверено: регрессии метки/инструкции воспроизведены до реализации;
`go test -race ./internal/chat ./internal/app ./internal/llm/codex/...`,
отдельный controller retry test и `make check` — PASS.
Windows EXE собран; реальный ответ модели с этой инструкцией не запускался.
