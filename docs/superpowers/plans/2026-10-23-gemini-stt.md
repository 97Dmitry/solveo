# Gemini 3.5 Transcribe Live — технический план

Цель: добавить третий рабочий `stt.Provider`, сохранив общий захват WASAPI, транскрипт, выбор реплик и хранение ключей. Основание: `docs/specs/solveo-design.md`, планы audio MVP и STT providers, запрос пользователя 2026-10-23.

Решение: прямой WebSocket Gemini API, существующий coder/websocket, без SDK, Docker и новых зависимостей. По одному соединению на источник. Модель `models/gemini-3.5-transcribe-live`, TEXT, VERBATIM, автоматическое определение языков, серверный VAD. Общий словарь (256 фраз, 128 символов, общий лимит 3800 байт) передаётся как `customVocabulary`; лимит приложения строже API (1000 фраз). Ключ только через `x-goog-api-key`, Credential Manager `Solveo/stt-gemini`.

Источники: [Transcribe Live](https://ai.google.dev/gemini-api/docs/live-api/live-transcribe), [форматы PCM](https://ai.google.dev/gemini-api/docs/live-api/capabilities), [официальный WS-клиент](https://github.com/googleapis/python-genai/blob/main/google/genai/live.py). Mono PCM16 LE с исходной частотой в MIME; ресемплинг выполняет Live API.

Риски и проверки: доступность модели и региона, точность IT-терминов, задержка двух источников требуют реального ключа. Разрыв/GoAway завершают только затронутый источник с явной ошибкой; автоматического повторения аудио и бесшовного восстановления в этой версии нет. Нельзя превращать неподтверждённый partial в final при ошибке.
