# Удобное продолжение разговора — Implementation Plan

**Goal:** выполнить шаг 3 roadmap: уточнять выбранный ответ, использовать короткие команды и заново отправлять изменённый вопрос без переписывания истории.
**Architecture:** Go сохраняет `reply_to_id` и `reply_to_kind` в черновике и новом пользовательском сообщении. Ссылка указывает на завершённый ответ текущего чата (assistant message либо approach/solution пользовательского хода). Codex получает точную цитату выбранного ответа в JSON текущего запроса, без повторной отправки истории в активную сессию. React только подготавливает редактор; отправка остаётся существующим Submit.
**Tech Stack:** существующие Go/Wails/React/Zod/Vite+, без новых зависимостей.
**Spec:** docs/roadmap/2026-10-21-core-features.md, раздел 3.

## Ограничения и решения

- Все команды сначала заполняют редактор; пользователь подтверждает отправку. Непустой текст и уже выбранную ссылку не заменять неявно.
- Копирование прежнего вопроса переносит текст и ссылку, без автоматического добавления прежних снимков; исходная история не меняется.
- Ссылка сохраняется вместе с ревизией черновика и сбрасывается только вместе с подтверждённой ревизией. Новый ввод во время генерации/сохранения остаётся доступен.
- При retry сохраняется исходная ссылка; новые входные поля retry не меняют зафиксированный вопрос.
- Неверная, чужая, незавершённая или направленная вперёд ссылка отклоняется до provider call; архивы без новых полей читаются как раньше.
- Получение частей определяется реальным stream preview, ожидание и запись — существующей фазой операции. Ошибки используют общий banner/recovery.
- Не менять provider state, инструкции, очередь снимков и native lifecycle.
- Windows runtime остаётся отдельной ручной проверкой. Не делать commit/push/PR.

## Проверяемые риски

1. Выбран старый ответ после новых реплик: в запрос попадает именно выбранная цитата.
2. Параллельные блоки: подход и решение адресуются независимо; незавершённый блок недоступен.
3. Сбой/перезапуск/повтор: ссылка восстанавливается и остаётся у исходного вопроса.
4. Новый ввод до/после завершения Submit: старое подтверждение не стирает свежий текст или ссылку.
5. Непустой редактор и IME: действия не затирают работу и не обходят защиту отправки.

## Результат проверки

- `make check` — пройден: bindings, frontend formatting/lint/types, 38 frontend tests, Go tests, host/Windows golangci-lint, Windows vet и сборка `build/bin/Solveo.exe`.
- `go test -race ./internal/...` — пройден; реальные provider requests не выполнялись.
- `git diff --check` — пройден. Итоговая самопроверка включила standalone approach для старого ответа, точный адресат/цитату, подтверждение ревизии, перенос черновика после discard и сохранение ссылки при ошибке чтения архива.
- Сборщик предупреждает о JS chunk >500 kB; новые зависимости не добавлялись.
- Windows/Wails UI, фокус и компактная вёрстка в native runtime не проверены; отдельный checklist — `docs/windows-acceptance.md`, раздел «Этап 3».
- Пользователь отдельно разрешил push и PR после проверки основных действий. Подробный Windows checklist остаётся отдельным; общая оценка «в остальном всё ок» не подтверждает каждый его сценарий.


## Исправление после пользовательской проверки: обычный ответ без кода

Пользователь получил только описание алгоритма при настройках по умолчанию,
без уточнений. В обычном Submit Purpose пустой; `codex.prompt` добавлял формат
решения только при Purpose=solution, который задавался в параллельном режиме.
Исправление: пустой Purpose использует ту же ветку формата, что и solution.
Требование кода остаётся условным (задача программирования); теоретическим
вопросам код не навязывается. Уточнения сохраняют свой формат, подход — запрет
кода. Контракты, общий instruction hash и provider state не меняются.
Регрессионный тест проверяет обычный текстовый и image-only ход. Реальная
генерация кода моделью требует повторной ручной проверки.

После исправления повторно пройдены `make check`,
`go test -race ./internal/app ./internal/history ./internal/settings ./internal/llm/...`
и `git diff --check`; `build/bin/Solveo.exe` пересобран.


## Дополнение: «Напиши код»

По запросу пользователя добавлена команда готового ответа «Напиши код»:
подготовить просьбу о полном рабочем коде исходного задания, учёте условий
и ограничений, кратком пояснении и сложности. Использует существующую ссылку
и Submit, без отдельного backend API, автоотправки или замены непустого
черновика. Проверка: UI-тест адресует команду выбранному старому ответу;
общий компонент делает её доступной также у завершённых параллельных блоков.
