# Быстрая отправка вопросов из расшифровки — технический план

> Работа в ветке задачи; Windows-приёмка — по `docs/windows-acceptance.md`, раздел «Быстрая отправка реплик и справка».

**Goal:** сократить путь «собеседник закончил вопрос → ответ в чате». Пользователь отметил, что основной чат отвечает примерно за 1 с, а сборщик вопроса добавляет около 3 с; ручное выделение фраз быстрее.

**Architecture:** две независимые части без новых зависимостей.

1. **Заготовка сессии сборщика.** `llm.QuestionPreparer` — необязательная возможность, аналог `ChatPreparer`: держит одну пустую эфемерную сессию анализа для модели/effort сборщика. Codex готовит её на вспомогательном app-server тем же `prepare`, что и заготовку чата (`thread/start` с инструкциями сборщика, без хода модели). `run` для анализа забирает заготовку по ключу модели/effort, пропуская `thread/start`, и после единственного хода освобождает её (`thread/unsubscribe`). Контроллер держит заготовку, пока сборщик активного чата включён: отключение, смена модели/чата и Close отменяют её; запуск анализа отвязывает заготовку, после анализа готовится следующая.
2. **Отправка новых реплик.** Каждая живая фраза получает признак `sent` после любого принятого submit, в который она вошла (выделение, карточка, новая команда). «Новые реплики» — все системные фразы после последней отправленной. `SendUnsentTranscript` проверяет чат и слот, запоминает ID и в зарегистрированном worker ждёт (до 6 с) окончания фраз, которые распознавались в момент нажатия, затем отправляет final через существующий `originTranscript`. Частичная фраза никогда не отправляется; речь, начатая после нажатия, не входит. Отправка вызывает `Builder.Consumed`: фразы исключаются из входа сборщика, автоматическая карточка из той же речи убирается, ручная/редактируемая сохраняется, текст становится последним вопросом для уточнений.

## Сопутствующие изменения

- Тайминги анализа (`Codex timing: purpose=question-analysis … prepared_thread=…`) попадают в журнал: `AnalyzeQuestion` получает `emit` только для progress-событий без содержимого.
- Debounce сборщика после system final сокращён с 800 до 300 мс: VAD уже ждёт 800 мс тишины перед final; интервал стартов ≥2 с сохранён.
- Новые глобальные действия добавлены в конец `hotkeys.Actions` (ID регистрации не меняются): `send-transcript` (по умолчанию Ctrl+Alt+Space), `toggle-listening`, `audio-window` (не назначены). При загрузке старых настроек новое действие получает значение по умолчанию, только если сохранённое действие ещё не занимает это сочетание.
- Окно распознавания: кнопка «Новые реплики (N)» с подсказкой сочетания, пометка «отправлено», состояние «Жду конец фразы…», ошибка отправки в `AudioAlerts`. Команда `sendUnsent` в allowlist IPC.
- Главное окно: панель «Справка и горячие клавиши» (кнопка «?»): все глобальные сочетания с текущими значениями, пометкой «не назначено» и ошибками регистрации, клавиши окна, частые вопросы; «Изменить сочетания» открывает настройки на вкладке «Клавиши».

## Review Focus

- Заготовка анализа не разделяется между анализами и не переживает смену модели; несовпадающая заготовка освобождается до хода. Подготовка не создаёт цикл перезапуска при ошибке: следующая попытка — только по событию (финал, включение, конец анализа).
- Повторное нажатие во время ожидания отклоняется; после ожидания фразы, отправленные другим путём, не отправляются второй раз.
- Порядок блокировок: `audio.mu` и `c.mu` не вкладываются; `markTranscriptSent` вызывается после освобождения `c.mu`.
- Таймаут ожидания показывает ошибку и ничего не отправляет.
