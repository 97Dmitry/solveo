# Единая голосовая история чата

Проблема: пользователь вынужден выбирать каждый Start/Stop как отдельный
сеанс, хотя это один разговор. Единица просмотра — открытый чат, все его
остановки/повторные запуски и провайдеры объединяются в хронологию.

Храним технические части отдельно, но каждый новый документ явно содержит
ChatID (и summary ChatID). Новая schema v2 читает старую v1. Старые части
с единственным Submission.ChatID можно безопасно включить в соответствующий
чат без перезаписи. Части без отправок или с несколькими чатами не угадываем:
они остаются доступны отдельно как старые записи без привязки.

Смена чата во время записи не перезапускает STT: создаётся новая логическая
часть с новым ChatID и теми же source streams. Уже начатая ASR-реплика сохраняет
свою прежнюю часть, новые — новую. Связь фиксируется при первом событии
utterance; поздний final не меняет принадлежность. Live список при смене чата
очищается; финал старой реплики сохраняется в старом чате, не всплывает в новом.
Никаких I/O под audio.mu/c.mu. Переключение истории не запускает распознавание.

UI: «История чата» читает всю хронологию текущего ChatID, без выбора отдельных
Start/Stop. Страницы по 300 остаются способом прокрутки больших списков, не
отдельными сеансами. Смена активного чата отменяет старую загрузку. Метаданные
провайдера сохраняются в частях и на архивных репликах. Удаление истории чата
удаляет его части, но не чужие/неоднозначные legacy; текущую запись надо
остановить. Старые без привязки остаются в отдельном fallback разделе.

Дополнительно по read-only проверке реального теста Qwen: обнаружены ошибки
shutdown Flush уже закрытых потоков. Исправить повторный Flush после Stop,
покрыть fake-regression. Qwen без аудио нельзя оценить количественно; отдельные
иностранные междометия отмечены как подозрительные, не удалять их автоматически.

Проверки: объединение Stop/Start одного чата, изоляция A/B, переключение во
время partial+late final, restart/load, legacy inference/unknown сохранение,
нет усечения на 200 технических частях, удаление/текущий чат, fake shutdown,
race + make check + Windows EXE. Пользовательские файлы только read-only.

Реализовано: v2 ChatID с чтением v1, объединение всей истории чата, явное прикрепление старых частей, изоляция уже начатых реплик при навигации, предупреждение при частичном чтении, исправление повторного Flush закрытых потоков. Проверки: frontend 98 tests, package race, make check и сборка Windows прошли; ручная Windows-проверка нового объединения пока ожидается. Реальные пользовательские файлы не изменялись.

Read-only проверка сохранённого Qwen-теста: четыре запуска, 25 окончательных реплик, два вопроса отправлены в один чат и получили завершённые ответы. Английские термины set/map/data race/race condition сохранились; замечены отдельные иностранные междометия и нестабильное написание goroutine. Исходного аудио нет: WER и сравнение с Gemini по этим данным не определяются. Две микрофонные части без отправок не имеют надёжного основания для автоматической привязки.
