# История, навигация и клавиатура — Implementation Plan

> **For agentic workers:** использовать superpowers:executing-plans, реализация в текущем checkout без commits/push/PR.

**Goal:** выполнить этап 6 roadmap: поиск, закрепление, экспорт, множественное удаление, настраиваемые хоткеи, производительность длинных разговоров.
**Architecture:** Go владеет архивом, закреплениями, поиском, экспортом и регистрацией хоткеев; renderer показывает результаты и записывает сочетания. Поиск внутри открытого разговора — только во frontend по уже отрисованному тексту.
**Tech Stack:** Go stdlib, Wails v2, React/TypeScript, CSS Custom Highlight API (Chromium/WebView2); без новых зависимостей.

## Решения пользователя (2026-10-22)

- Экспорт: папка `solveo-data/exports/<UTC-время>-<название>/` с `chat.md` и `images/*.png`, затем явное «Открыть папку» в Проводнике. Системного диалога нет.
- Хоткеи задаются записью нажатия; на время записи Go снимает регистрацию глобальных хоткеев.

## Принятые допущения

- Закрепления хранятся в `solveo-data/pins.json`, а не в документе чата: закрепление не переписывает архив до 32 МиБ и не меняет `updated_at`. Повреждённый файл трактуется как пустой и перезаписывается при следующем изменении; файл новой версии не перезаписывается.
- Порядок истории задаёт Go: закреплённые сверху, внутри групп — по `updated_at`.
- Поиск по истории — регистронезависимая подстрока (Unicode, по рунам) в названии, вопросах и ответах (включая блоки параллельного режима); преднастройка, черновики и снимки не ищутся. Линейный проход по архиву без индекса, до 50 результатов, отмена устаревшего запроса.
- Экспорт содержит название, даты (UTC), вопросы, ответы, статусы незавершённых ходов и снимки. Преднастройка, общие инструкции и provider state не экспортируются.
- Удаление активного чата в наборе: Go сначала переключает на самый новый невыбранный чат, иначе создаёт новый; черновик и очередь удаляемых чатов удаляются вместе с ними после подтверждения.
- Настраиваются пять глобальных хоткеев (снимок → ответ, показать/скрыть, в очередь, отправить, весь экран → ответ). Пустое значение отключает действие. Обязателен Ctrl, Alt или Win. Внутриприложенческие клавиши (Enter, Ctrl+F, Escape) фиксированы.
- Ошибка регистрации хоткея при запуске больше не фатальна: приложение стартует, состояние каждого хоткея видно в настройках, трей остаётся путём выхода.

## Global Constraints

- Текущий checkout; без commits/push/PR.
- I/O вне `c.mu`; новые workers регистрируются для Close; ошибки UI по-русски; время в Go — UTC.
- Generated bindings только через `make bindings`; новые поля snapshot проверяются Zod против DTO.
- Схема settings остаётся v1: поле `hotkeys` аддитивное, отсутствие → значения по умолчанию; тема, масштаб, шрифт и закрепление окна не меняются.

## Review Focus

1. Удаление: сбой после переименования папки снимков не оставляет снимки без чата и не удаляет снимки существующего чата при последующей очистке.
2. Множественное удаление с активным чатом и частичным сбоем: результат по каждому чату, черновик/очередь неудавшихся сохраняются.
3. Хоткеи: применение новой раскладки транзакционно (откат при конфликте или ошибке записи settings); пауза записи не остаётся навсегда после reload/blur.
4. Поиск: устаревшие ответы не перезаписывают новые; Close ждёт поисковый worker.
5. Длинный чат: ввод текста не вызывает повторный разбор Markdown всех сообщений.

## Результаты

- `make check` пройден: bindings, frontend check/typecheck, 70 frontend-тестов,
  Go-тесты, golangci-lint host/Windows (0 issues), Windows vet, сборка
  `build/bin/Solveo.exe`. `go test -race -count=1 ./internal/...` пройден.
- Замер длинного разговора (jsdom, 300 ходов с Markdown и кодом,
  `src/chat/long-chat.test.tsx`): до — 36–96 мс на каждый snapshot и столько же
  на каждое нажатие клавиши (ChatView без мемоизации, нестабильные callbacks);
  после — snapshot 7–12 мс, нажатие 0,1–0,5 мс, порция потока ≈7 мс, разбор и
  сравнение snapshot 1,3–3,3 мс. Markdown уже был мемоизирован; стоимость была
  в сверке ~600 строк. Виртуализация не добавлена.
- Отклонения от плана: отдельный `internal/hotkeys` вместо разбора в settings;
  экспорт реализован в `internal/history` (архив владеет путями снимков);
  `DefaultHotkeys` экспортируется из Go, чтобы frontend не дублировал значения.
- Независимое ревью отдельным агентом не запускалось (агенты не запрошены);
  выполнено самостоятельное ревью diff. Найдено и исправлено RED→GREEN:
  удаление активного чата не закрывало нативный просмотрщик его снимков
  (`TestDeletingActiveChatClosesImageViewerFirst`). Выровнены названия
  действий в ошибках Go и подписи UI.
- Ограничения: поиск истории без индекса читает весь архив; поиск в разговоре
  не находит совпадения через границы форматирования; Проводник при
  «Открыть папку» не исключён из захвата; приостановка хоткеев снимается не
  позже чем через 60 с даже при незавершённой записи.
- Windows runtime не проверен: регистрация и конфликты RegisterHotKey,
  запись при занятом сочетании, ShellExecute/Проводник, CSS Highlight в WebView2,
  блокировки файлов при удалении и реальная производительность длинного чата —
  раздел «Этап 6» в docs/windows-acceptance.md.
- По отдельному разрешению пользователя изменения опубликованы в ветке
  `feat/history-navigation` (вместе с отдельным коммитом иконок) и PR на `master`.
