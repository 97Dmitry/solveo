# Профили подготовки интервью

Статус: реализовано по шагу 4 roadmap после разрешения пользователя; Windows/Wails-приёмка остаётся отдельной.

## Задача и границы

Повторно использовать подготовку интервью без ручного копирования и без
генерации ответа при сохранении или применении. Профиль — именованный снимок
`chat.Config`, а не чат и не сессия Codex. Редактирование и удаление профиля
не меняют уже созданные чаты. PDF, генерация резюме, встроенные примеры опыта,
синхронизация и новые подключения в этап не входят.

## Предлагаемые решения

- Добавить в `chat.Config` необязательные строки `position`, `stack`,
  `interview_format`, `experience`. Старые архивы читаются с пустыми полями.
  Остальной свободный контекст остаётся в `context`, пожелания — в
  `instructions`; языки, подробность, основные и быстрые model/reasoning,
  `parallel_answers` сохраняются без потерь.
- Поле «Реальный опыт и проекты / текст резюме» допускает ручной ввод и вставку.
  Оно по умолчанию пустое. Инструкции модели явно запрещают придумывать
  работодателей, стаж, проекты, достижения и метрики; при отсутствии фактов
  модель должна уточнить данные либо дать явно обозначенную заготовку.
  Это инструкция модели, а не программная гарантия достоверности её ответа.
- Новый пакет `internal/profiles`: отдельный версионированный документ
  `solveo-data/profiles.json`, атомарная замена через `storage.Replace` и
  ограничение доступа через `os.Root`. Профиль содержит ID, название, Config,
  ревизию, CreatedAt/UpdatedAt UTC. Общие инструкции, название исходного чата,
  сообщения, вложения и provider state в профиль не входят.
- Имя после TrimSpace: 1–160 Unicode code points; максимум 100 профилей.
  Каждое текстовое поле Config ограничено существующим пределом 1 MiB,
  UTF-8 должен быть корректным, NUL запрещён; документ ограничен 32 MiB.
  Одинаковые имена допустимы: идентичность определяется ID.
- Чтение испорченного или более нового документа показывает отдельную ошибку
  профилей и запрещает его перезапись. Обычные чаты продолжают работать.
  Отсутствующий файл означает пустую библиотеку. Ошибка записи не изменяет
  принятую в памяти версию. Обновление и удаление проверяют expected revision.
- В преднастройке доступны выбор профиля с немедленным заполнением формы,
  «Сохранить как профиль», «Обновить профиль», «Удалить профиль» и «Новый чат из профиля».
  Сохранение профиля использует текущие поля формы, не применяя их к чату.
  Выбор профиля заменяет только поля формы; при наличии ручных правок
  требует подтверждения. Неизменённые профили переключаются без подтверждения; применение к текущему чату — отдельное существующее сохранение.
  Удаление требует подтверждения. Несохранённое имя чата не является именем
  профиля: для него отдельное поле.
- «Новый чат из профиля» использует сохранённую ревизию профиля, сохраняет
  новый локальный чат с копией Config и актуальным snapshot общих инструкций,
  затем переключает UI. При сбое записи остаётся текущий чат. Его черновик и
  очередь сохраняются. Название нового чата — имя профиля; редактируется отдельно.
- Создание чата и применение конфигурации доступны в idle по существующим
  правилам. Все операции библиотеки также сериализованы контроллером; I/O
  выполняется вне mutex. Неверные ID/ревизии отклоняются без изменений.
- Сохранение профиля не обращается к провайдеру. Создание чата из профиля и
  явное сохранение преднастройки сохраняют существующую фоновую подготовку
  `PrepareChat` (инициализация сессии без `turn/start`); генерация, Submit и
  сообщения отсутствуют до явного вопроса. Это трактовка требования roadmap
  «без LLM-запроса»: без запроса генерации, с сохранением уже принятого прогрева.
- Каталог моделей используется существующий. Ошибка его загрузки не стирает
  профиль; после успешной загрузки недоступные параметры показываются и
  требуют исправления для применения, без молчаливой замены модели.

## Приёмка

Сохранить профиль с резюме и всеми параметрами, перезапустить приложение,
создать два чата из профиля. Изменить/удалить профиль: оба чата сохраняют
исходные настройки, каждый содержит собственный snapshot общих инструкций.
Ни одна операция профиля не вызывает Generate; подготовка нового чата не
вызывает turn/start. Отправка вопроса использует поля опыта и подготовки в
основном и быстром запросах. Повтор использует зафиксированный RequestConfig.
Пустой опыт не пополняется автоматически. Windows UI проверяется отдельно
от сборки и автоматических тестов.
