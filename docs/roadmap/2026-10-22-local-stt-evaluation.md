## Spike: что подтверждено

- Контейнер с `--network none` загружает модель и распознаёт: ленивых загрузок нет.
- Streaming API (`chunk 1 с`, rollback 2/5 по upstream) и offline `transcribe()` работают на одном экземпляре vLLM последовательно.
- 20-секундная принудительная граница работает (фрагмент 32,8 с → 2 состояния).
- 10 с цифровой тишины: пустой вывод в обоих режимах.

## Spike: найденные проблемы

1. **Память.** Конфигурация vLLM по умолчанию (8192 batched tokens, профилирование энкодера на 20 аудио) при `gpu_memory_utilization=0.7` не стартует: KV cache −1,91 ГиБ. Рабочая настройка: `max_num_batched_tokens=2048`, `limit_mm_per_prompt={"audio": 1}`, KV cache 1,27 ГиБ. Пик GPU 7144 МиБ при 569 МиБ до запуска: процесс занимает ~6,4 ГиБ, **больше предложенного gate 6 ГиБ**. Следующий шаг — замер при `gpu_memory_utilization` 0,6.
2. **Cold load 87–94 с** (из них torch.compile ~38 с) при readiness-бюджете 120 с. Кэш компиляции живёт в `/tmp` контейнера и теряется; постоянный кэш — вопрос для 9.1.
3. **Прогрев.** Первый decode-шаг 5,5 с; runner прогревает модель на 2,5 с тишины (`warmup_sec` ≈ 6,4 с) до замеров.
4. **Скрытая ошибка регистрации.** qwen-asr регистрирует модель в vLLM внутри `except: pass`. При запуске под uid без записи в passwd torch падает в `getpass.getuser()`, и vLLM сообщает только «architecture not supported». Образ задаёт `HOME`/`USER`, runner явно проверяет регистрацию. Worker 9.1 обязан делать ту же проверку.
5. vLLM грузит токенизатор без `fix_mistral_regex=True` (предупреждение о некорректном regex), процессор qwen-asr — с ним. Влияние на кодирование prompt/prefix не измерено.
6. Под WSL `torch.cuda.mem_get_info` не видит процесс EngineCore (показывает 1,7 ГиБ при фактических 7,1 ГиБ); память снимается только nvidia-smi на хосте.

## Что нужно для решения

1. Корпус по README `tools/audio-bench`: сначала 20–30 своих mixed RU/EN фрагментов для быстрого отсева, затем ≥120 фрагментов / 30 мин, ≥5 говорящих, dev/holdout 2:1.
2. Прогоны на dev: chunk 1 и 2 с, context и без него, нерелевантный context; выбор режима final (streaming или hybrid) до holdout.
3. Замер памяти при `gpu_memory_utilization` 0,6, 30 минут непрерывной работы, VAD/endpointing.

## Быстрый отсев на записях пользователя (2026-10-23)

Корпус: `tools/audio-bench/corpus/` (`phrases.txt`, `annotations.json`; аудио не в git). 30 зачитанных фраз одного говорящего, микрофон ноутбука, AAC 48 кГц: 20 mixed RU/EN, 3 RU, 3 EN, 2 длинные с паузой, тишина и шум. Термины и критичные места размечены до первого прогона. Это отсев, а не holdout: один говорящий, читаемый текст, разметка автора скрипта.

| Прогон | WER stream / offline | mixed WER | Термины stream / offline | Критичные | Тишина/шум |
| --- | --- | --- | --- | --- | --- |
| chunk 1 с, словарь (3 повтора) | 14,0–14,9% / 13,8% | 15,5–16,6% / 15,2% | 45–46 / 47 из 63 | 9/12 | 0/2 |
| chunk 1 с, без словаря | 24,0% / 20,7% | 27,2% / 23,4% | 29 / 32 из 63 | 9/12 | 0/2 |
| chunk 2 с, словарь | 14,0% / 13,8% | 15,5% / 15,2% | 46 / 47 из 63 | 9/12 | 0/2 |

Задержка (replay, endpoint silence 0,8 с), chunk 1 с со словарём: p95 partial lag 1,2 с; p95 final 0,95 с (streaming) и 1,4–1,6 с (hybrid); две дорожки 1,4 / 1,0 / 1,9–2,1 с; RTF 0,15 / 0,18. Chunk 2 с: partial lag 2,3 с, качество то же. Пик VRAM 7,4–7,9 ГиБ при 1,2 ГиБ до запуска (~6,2–6,7 ГиБ на процесс). RAM контейнера до 3,9 ГиБ.

Выводы:

- **Словарь (context) обязателен:** без него термины 29/63, «context cancellation» → «контекст консолидации», «goroutine» → «грудину». Со словарём остаются ошибки: `goroutine` → «гурудину»/«горутину», `localStorage` → «локал стореж» (offline верно), `repeatable read` → «repeat был read», `eventual consistency` → «внешнюю консистенцией», `garbage collector` → «гибридный коллектор», `lock` → «лог».
- **Потеря отрицания:** q19 «Не используй any…» → «использую Any…» в обоих режимах во всех прогонах: смысл инвертирован. Gate ≥98% по критичным местам не пройден.
- **Не на том языке и не тем алфавитом:** q05 «таймアウト» — японская катакана посреди русского слова.
- **Начало фразы:** в q10, q14, q15 и q19 первое слово теряется или искажено в обоих режимах. Записи начинаются с 0,2–0,35 с цифровой тишины (AAC); обрезка первого слога самой записью не исключена.
- **Недетерминизм и разгон генерации:** при temperature 0 повтор 2 дал на q14 4 decode-шага по ~3 с (вывод до лимита 256 токенов, `finish_reason=length`); p95 final для двух дорожек вырос до 5,8 с. Worker 9.1 обязан ограничивать токены на streaming-шаг (upstream пример — 32) и считать такой шаг ошибкой.
- **Hybrid final** (offline на endpoint) со словарём почти не лучше streaming (WER −0,2 п.п., +1 термин), без словаря лучше на 3,3 п.п. Цена — +0,5 с к final.
- **Разметка O-нотации неоднозначна:** говорящий произносит «O большое n…», модель пишет так же, а эталон — `O(n log n)`. Это 4 термина и 1 критичное место в q06, q16, q28, засчитанные как ошибки; варианты не добавлялись после прогона. Даже без них термины ≈ 50/63 (79%).

### Настройка Qwen (2026-10-23)

Новые параметры runner по умолчанию: `gpu_memory_utilization=0.6`, `max_model_len=2048` (KV cache 0,47 ГиБ — для реплик ≤20 с с context достаточно), лимит 32 токена на streaming-шаг, 256 на offline. Пик VRAM 7,06–7,22 ГиБ при 1,32 ГиБ до запуска: **~5,7–5,9 ГиБ на процесс, gate ≤6 ГиБ пройден** с малым запасом.

| Прогон (chunk 1 с) | WER stream / offline | mixed stream / offline | Термины stream / offline (без O-нотации) | Тишина/шум |
| --- | --- | --- | --- | --- |
| прежний: 0,7, словарь-инструкция | 14,0 / 13,8% | 15,5 / 15,2% | 46 / 47 из 59 | 0/2 |
| 0,6 + лимит 32, словарь-инструкция | 14,9 / 13,8% | 16,6 / 15,2% | 45 / 47 из 59 | 0/2 |
| словарь только списком терминов | 16,5 / 14,0% | 19,0 / 15,5% | 42 / 45 из 59 | 0/2 |
| язык принудительно Russian | 15,2 / 14,9% | 16,6 / 16,6% | 47 / 47 из 59 | **2/2** |

- **Залипание streaming:** в q14 после «…почему Explain на» каждый шаг упирается в лимит токенов, а текст не продвигается; итог streaming теряет конец фразы. Offline-проход той же реплики даёт её целиком. Явление недетерминированное (2 из 5 прогонов). Лимит токенов ограничил цену по времени (p95 final для двух дорожек 1,2 с вместо 5,8 с), но не потерю текста.
- **Принудительный Russian отклонён:** на тишине и шуме модель выдаёт «context cancellation» из словаря.
- **Словарь только списком хуже**, чем инструкция со списком; оставлен шаблон-инструкция.
- **Рекомендуемый режим final — hybrid:** offline-проход не хуже streaming ни в одном прогоне и исправляет залипание и ранние ошибки ценой ~0,5 с (p95 final 1,4–1,5 с; две дорожки 1,9–2,1 с, в пределах gate 3 с). Окончательно выбирается после повторного отсева.
- Подбор параметров не меняет главного: термины ≈ 80% (47 из 59 без O-нотации). Оставшиеся ошибки — акустические, на уровне отдельных слов: `goroutine`, `localStorage`, `repeatable read`, `eventual consistency`, `garbage collector`, `lock`→«лог», `latency`→«латенция», `two-phase commit`→«Two Phases Commit».

Gates плана (предварительно, один говорящий): mixed WER ≤15% — на границе (15,2–16,6%); термины ≥95% — не пройдено (73–79%); критичные ≥98% — не пройдено; тишина — пройдено; задержка и RTF — пройдено; VRAM ≤6 ГиБ — не пройдено при 0,7 (~6,2–6,7 ГиБ), пройдено при 0,6 (~5,7–5,9 ГиБ).

## Решение (2026-10-23)

Пользователь принял Qwen3-ASR-1.7B с hybrid final и снизил порог по терминам до ≥80%: карточку вопроса можно исправить вручную до отправки. Остальные gates без изменений. Параметры зафиксированы в плане, раздел «Решения 9.0».

Разметка O-нотации исправлена до повторного отсева: говорящий произносит `O(...)` как «O большое …», эти формы добавлены вариантами в q06, q16 и q28. Пересчёт прогона `v2-base` с исправленной разметкой: термины streaming 48/63, hybrid 50/63 (79%); критичные места 10/12 в обоих режимах.

Перед повтором отсева перезаписываются q10, q14, q15 и q19 (`tools/audio-bench/corpus/rerecord.txt`): обе модели независимо теряют в них первое слово, значит, обрезана сама запись.
