# Speech recognition window

- The header «Распознавание речи» button opens a detached Wails renderer; no audio panel is mounted in the chat. window-main.tsx/audio.html are the separate entry. AudioWindow polls validated parent state sequentially every 200 ms; the parent owns all state. Closing hides the renderer without stopping recognition. Child commands go only through bridge/wails.ts; send/insert carry the displayed ChatID. Insert is acknowledged by the main renderer to protect its live draft/IME. Do not add a second SolveoClient connection in AudioWindow.
- Layout: a header (target chat, dock icon, `SessionControls`), `AudioAlerts`, then Radix Tabs «Эфир / История / Словарь / Настройки». The tab is child-local state; polling never changes it. Live, dictionary and settings panels are `forceMount` + `hidden` so phrase selection, QuestionCard edits and form input survive tab switches; History mounts only while open. Hide the History tab when `history_enabled` is false. Check layout manually (jsdom does not lay out) at 460×680 and the 380×360 minimum.
- `SessionControls` is the only place for the session lifecycle: start model/connect (`start_label`, only when all checks pass) → Слушать → Остановить; otherwise «Настроить» opens settings. It requests the first readiness check once per opening and per provider. It never decides readiness itself; `readiness.ts` only reads Go's checks.
- Current source/controller/history/window errors stay in `AudioAlerts`, visible on every tab. Show docked state and window_error separately from STT errors; dock/float is handled locally in the child and stays available while the main LLM is busy. Docking never takes space from the chat.
- `RecognitionSettings` (settings tab): provider selector (only while nothing runs), privacy line, key form, checks, Подготовить/Проверить снова/unload (`stop_label`), sources. Provider wording comes from `audio.provider`. The saved key is never shown: the field is write-only and clears after saving.
- `LiveTranscript` keeps only the phrase selection locally; selections of vanished or still-partial phrases are dropped on every render. Partial phrases are visible but not selectable. Отправить passes segment IDs in transcript order (Go builds the text, the draft is untouched); В поле ввода joins the selected texts with newlines. «Очистить расшифровку» clears only live rows, never the archive. Nothing is sent automatically. «Новые реплики (N)» (`sendUnsent`) counts system phrases after the last `sent` one with `unsentCount` (mirrors Go) and shows «Жду конец фразы…» while Go waits; sent rows are marked «отправлено»; `send_error` shows in AudioAlerts.
- `AudioHistory` is the history tab: loads the current chat timeline (forChat) when the tab opens and on ChatID changes, guards stale requests with an epoch, pages at 300 and opens on the latest page. Search filters the whole document before paging. Rows are plain selectable text (not buttons) and never join the live transcript. Only current-chat history; no legacy list, per-part picker or assignment controls. Show the archive Notice for unreadable parts even when no readable rows remain. Metadata, errors, submissions, dictionary, devices and deletion (explicit confirmation) stay under collapsed «Подробности».
- `QuestionCard` stays above the transcript on the live tab; Go owns card readiness/freshness. A disabled empty builder collapses to one line («Включить сборщик» or «Выбрать модель» → settings). Editing immediately freezes the parent card; local text is keyed only by ChatID so first-card ID assignment and polling cannot erase typed text. Save carries the text explicitly. Rebuilding a nonempty manual version requires explicit in-panel confirmation. No default model, no automatic send.
- `QuestionSettings` holds enable/disable and model/effort from the provider catalog. AudioWindow requests the catalog only on the explicit switch to the settings tab when it is empty, never in the background.
- Show draft as «Черновик вопроса», not a running analysis. can_confirm is parent-owned and enables explicit «Подтвердить этот текст» without editing/submitting; only analyzing says «Собираю вопрос…». Pending system speech/analysis/error must never be locally promoted by a timer. Polling still owns the accepted confirmation result.
- `DictionarySettings` (dictionary tab) is the only editor of the recognition dictionary: View.dictionary is the saved list, «Сохранить словарь» sends `setDictionary` with trimmed non-empty lines; Go normalizes, validates and persists. Local text follows the saved list only while untouched, so polling never erases edits. Limits shown come from `audio.provider`.
- Tests: `vp test run src/audio`.
