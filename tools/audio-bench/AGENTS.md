# Stage 9.0 STT benchmark

- Opt-in measurement tool for the local Qwen3-ASR decision (plan `docs/superpowers/plans/2026-10-22-local-audio.md` §3, §8 9.0). Not application code: nothing in `internal/` imports it, `make check` does not run it.
- `audio_bench/{metrics,manifest,report,timeline}.py` are standard-library only and run on the host. `runner.py` needs numpy; `run_qwen.py` runs only inside the image built from `docker/Dockerfile`.
- Pins are a contract: base image digest, `docker/requirements.lock` (`--no-deps`, so every transitive package is listed) and model revision `7278e1e70fe206f11671096ffdd38061171dd6e5`. Bump them together and record the change in the evaluation report; never `pip install` or download weights at run time. Run measurement containers with `--network none`.
- `runner.py` mirrors the semantics of qwen-asr 0.0.6 (`init_streaming_state`/`streaming_transcribe`/`finish_streaming_transcribe`, one `model.generate` per full chunk, no decode on an empty tail). `tests/test_runner.py` fakes exactly that; re-read upstream `qwen_asr/inference/qwen3_asr.py` when the pin changes.
- Metric rules (normalization, pooled rates, nearest-rank p95, endpoint-silence replay) are documented in README and tested; changing them invalidates earlier results. `CONTEXT_TEMPLATE` is frozen before holdout.
- Corpus audio, references and results stay outside git unless distribution rights are confirmed. `corpus/` holds the user's quick-screening recordings: only `phrases.txt` (`id | recording | reference`, ` / ` marks a spoken pause and is not part of the reference) and `annotations.json` (terms/critical fixed before the first run; never add variants after seeing output) are tracked, its `.gitignore` excludes everything else. Synthetic SAPI audio proves only the pipeline, never quality.
- Grok comparison: `audio_bench/run_grok.py` uploads each corpus WAV to xAI's batch STT (stdlib HTTP, key only from `XAI_API_KEY`, never written to results); results use the run_qwen schema with empty streaming steps. Tests use a local fake HTTP server.
- Nemotron comparison: `audio_bench/nemotron.py` + `run_nemotron.py`, image `docker/nemotron.Dockerfile` (transformers 5.19.0 replaces the base's 4.x, so vLLM is unusable there). Regenerate either lock with `docker/lock-delta.sh <pip args>`; never hand-edit a freeze diff. Nemotron was rejected for mixed RU/EN (see the evaluation report) — keep it only as a comparison baseline.
- Validation: `make audio-bench-test`; image: `make audio-bench-image`; GPU smoke per README.

- To reproduce the current worker context, pass `run_qwen --pronunciations <worker solveo_stt/pronunciations.json>` with the instruction template. Hints apply only to the offline final; streaming uses canonical-only context. Both context hashes are recorded. Omitting it intentionally retains the canonical-only baseline. Header records the pronunciation-file digest; the contract test compares worker and runner contexts, including dictionary byte limits. Mount this small asset read-only into the measurement container; do not duplicate the hint table.
