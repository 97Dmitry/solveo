# Solveo engineering notes

- Windows x64 desktop application: Go + Wails v2, React/TypeScript frontend generated with Vite+ (`vp`). Use pnpm only; preserve `frontend/pnpm-lock.yaml`.
- Work in this checkout. No commits, pushes or releases unless explicitly requested. Source project `/home/dmitry/my_projects/screen-codex` is read-only during the port.
- Read `docs/specs/solveo-design.md` before changing architecture. The initial implementation plan is under `docs/superpowers/plans/`; execution evidence is under `.superpowers/sdd/`.
- The agreed development roadmap is [docs/roadmap/2026-10-21-core-features.md](docs/roadmap/2026-10-21-core-features.md): automatic request handling and early useful answers first, core features before audio. Prepare a scoped technical plan for each stage before implementation.
- Create and maintain a local `AGENTS.md` for every module or directory that contains complex logic. Use these files to separate context: keep project-wide rules here and put module responsibilities, invariants, constraints and relevant validation commands in the owning directory's instructions. Read the applicable local instructions before changing that module.
- Whenever creating an `AGENTS.md`, create an adjacent `CLAUDE.md` containing `@AGENTS.md` to import the same instructions. Keep `AGENTS.md` as the single source of truth; do not duplicate its contents in `CLAUDE.md`.
- Keep local instructions concise and current. Do not repeat parent instructions, document obvious directory structure or create instruction files in trivial folders solely for coverage. Update the owning module's instructions when its important behavior or constraints change.
- Scope guides: [frontend](frontend/AGENTS.md), [Go backend](internal/AGENTS.md), [native Windows host](internal/platform/windows/AGENTS.md), speech recognition: [audio capture](internal/audio/AGENTS.md), [worker client](internal/stt/AGENTS.md), [local Qwen provider](internal/stt/qwen/AGENTS.md), [Grok provider](internal/stt/grok/AGENTS.md), [Gemini Live provider](internal/stt/gemini/AGENTS.md), [worker](internal/stt/worker/AGENTS.md), [secrets](internal/secrets/AGENTS.md).
- Speech recognition is implemented by [the audio MVP plan](docs/superpowers/plans/2026-10-23-audio-mvp.md) and [the providers plan](docs/superpowers/plans/2026-10-23-stt-providers.md): the controller reaches recognizers only through `stt.Provider` — local Qwen3-ASR in the self-built `solveo-stt` image ([qwen](internal/stt/qwen/AGENTS.md)) or cloud xAI ([grok](internal/stt/grok/AGENTS.md)) / Google Gemini Transcribe Live ([gemini](internal/stt/gemini/AGENTS.md)), chosen explicitly by the user; keys live in [secrets](internal/secrets/AGENTS.md). No automatic fallback between providers. Tests never use real Docker, GPU, audio devices or models; `make check` includes `stt-worker-test` (needs `uv`).
- UI work should use libraries and packages instead of hand-rolling what an established package already does well (components, accessibility, formatting, virtualization, etc.). Add only current, actively maintained and widely adopted packages: recent releases, broad usage, no deprecation or abandonment. Prefer the latest stable major, justify bundle-size impact, and add them with pnpm so `pnpm-lock.yaml` pins them.
- Go owns business state. Wails owns the main UI thread; Win32 helper windows run on a separate locked host thread. Workers never access native windows directly.
- `make bindings` runs the headless host-native entrypoint; never apply Windows GOOS to it. Generated bindings stay in `frontend/wailsjs`; do not edit them by hand.
- Main Wails window starts hidden. DOM/native readiness and renderer handshake precede the first show; reloads and pin changes never show it. It never appears in the taskbar or Alt+Tab (tray only). Apply capture affinity before showing any top-level window and preserve a usable exit path.
- Codex is the only implemented LLM adapter. Do not add placeholder provider/audio controls. Preserve the provider boundary when adding real adapters.
- `make check` regenerates bindings, checks frontend formatting/lint/types/tests, runs Go tests, golangci-lint (host and Windows, config in `.golangci.yml`, pinned binary in `.tools/<lint>-<go>/`, rebuilt per host Go version because the linter needs Go ≥ the analyzed stdlib) and Windows vet, and builds `build/bin/Solveo.exe`. Apply Go import grouping with `golangci-lint fmt` from that directory; intentionally ignored errors are explicit `_ =`. It does not verify Windows UI or recorder behavior; use `docs/windows-acceptance.md` for native runtime acceptance.
- Tests must not issue real provider requests; use fake CLI scripts. User-facing documentation should describe actual setup, use, data storage and limitations.

- Detached audio renderer: same EXE `--audio-window`, isolated from singleton/stores/providers; parent-owned IPC is documented in [internal/audiowindow](internal/audiowindow/AGENTS.md). Frontend has main/audio HTML entries. Under wails dev the child uses embedded assets; rebuild frontend and restart the app to update that window (no child HMR).

- Text ASR archives are technical parts grouped by ChatID in solveo-data/audio-history, owned by [internal/audiohistory](internal/audiohistory/AGENTS.md) and internal/app/audio_history.go. No audio recording, keys or provider state are persisted there.

- Fast interviewer questions ([plan](docs/superpowers/plans/2026-10-23-fast-transcript-questions.md)): «send new phrases» (hotkey send-transcript) sends every system phrase after the last sent one without the builder; the builder keeps a prepared Codex analysis session while enabled. The main window has a help panel listing all hotkeys.

- Interview question cards: [internal/questionbuilder](internal/questionbuilder/AGENTS.md) owns the bounded state machine; internal/app/question_builder.go owns scheduling, model preferences and explicit submission. Cards live above the detached audio transcript; only accepted versions persist in chat messages. Analysis is independent of the main generation slot and uses a separate lazy Codex transport.
