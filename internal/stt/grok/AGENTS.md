# Grok (xAI) cloud provider

- Audio leaves the computer: this provider is only used when the user selects it, and the panel marks it as cloud. The key is read through `keys()` (secret store, `stt.KeyName("grok")`) on every check/start and is never part of an error, a URL, a log or an event; dial errors map 401/403 to «Ключ отклонён xAI».
- Streaming endpoint `wss://api.x.ai/v1/stt` (tests override `Provider.URL`), bearer header, query `model=grok-voice-transcribe-2.0&encoding=pcm&sample_rate=<device rate>&interim_results=true&endpointing=800` plus one `keyterm` per dictionary phrase (≤ 100, ≤ 50 characters, enforced in `Open`). One WebSocket per stream, dialled on the first frame; frames are downmixed to mono PCM16 at the native rate (no resampling); rates outside 8000/16000/22050/24000/44100/48000 fail the stream.
- `assembler` maps `transcript.partial` to stt updates: interim → partial, `is_final` → locked chunk, `speech_final` → final of the whole utterance. xAI does not document whether finals repeat locked text, so both forms are accepted without duplication. `Flush` sends `Finalize` and waits ≤ 3 s; silence means nothing was pending. A stream error never ends the session. `error` events are remembered, not fatal (xAI keeps the connection on parse errors); the stream fails only when the socket closes, with the last error message. A pending utterance is finalized with its latest text on `transcript.done` or when the stream ends, so it can still be sent. Locked/final text is compared by words (case, punctuation and spacing ignored). Handshake failures show the HTTP status and xAI's error text; 401 means a rejected key.
- Open questions to verify with a real key: chunk assembly, Finalize without speech, idle timeouts. Tests: `go test -race ./internal/stt/grok` (fake xAI server).
