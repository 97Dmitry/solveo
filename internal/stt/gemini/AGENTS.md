# Gemini Transcribe Live

- Implements `stt.Provider`/`SessionAPI` directly over Gemini API v1beta BidiGenerateContent. Model `gemini-3.5-transcribe-live`, response TEXT, VERBATIM, language auto-detection. Server VAD; no LLM response generation. Validate setupComplete before capture starts.
- One socket per source, opened by Open; Push downmixes to mono PCM16 LE at the declared native device rate (Live API resamples). A bounded 50-frame queue preserves audio/control order; Push never waits for network. Flush sends audioStreamEnd after queued audio and waits at most 3 seconds. If interim text remains unconfirmed when that wait expires, return an error; silence with no pending interim needs no final acknowledgement. CloseStream is cancellation; callers Flush first to preserve the last phrase.
- Interim hypotheses replace the current partial. inputTranscription is authoritative final. Never finalize a partial because the socket closed. Empty final removes an existing hypothesis. Vendor timestamps are unavailable; sample positions stay zero.
- Disconnect, malformed message, error or GoAway produces a source-specific error. No automatic reconnect/replay/resumption: the user restarts listening. Session Close cancels pending setup/writes/reads and joins goroutines before closing Events. As for other providers, callers must continuously drain Events.
- Key getter reads Credential Manager target `Solveo/stt-gemini` on each Status/Start. Authenticate only using x-goog-api-key; never put a key in URL/settings/events/errors/logs. Do not reflect raw vendor errors. Status/Start opens a no-audio model session, which still requires API access/quota.
- Dictionary uses application limits 256 phrases / 128 code points (settings additionally enforce 3800 bytes); API limit is 1000 phrases, Google recommends about 100. No silent trimming.
- Run `go test -race ./internal/stt/gemini`; fake WS only. Real key/model availability, code-switching quality, native-rate acceptance and latency remain a separate opt-in acceptance.
