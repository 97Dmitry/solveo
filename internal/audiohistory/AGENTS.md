# Audio text archive

- Version-2 ASR parts with required ChatID (no legacy reading or migration), text only: no PCM, credentials or provider state. DTOs and validation here are the archive contract; controller must validate final rows before scheduling persistence.
- Files are `<32 lowercase hex>.json` directly under the configured directory. All archive file operations use `os.Root`; only Save creates storage. Errors must not expose raw documents, paths or credentials. Save preserves unsupported, corrupt or identity-mismatched existing documents. Session ID, StartedAt, ProviderID and required 32-hex ChatID are immutable.
- Document field order is `version`, `summary`, `session`. ForChat scans all bounded headers and sorts matching parts chronologically, without a 200-file cap. Version-1 and unbound headers are silently ignored: no warning, inference from submissions, assignment API or automatic rewriting. Other unreadable/corrupt headers still return readable parts plus an error; Load validates the body and summary consistency. Reads never create or migrate files.
- Limits: 10000 final segments, 32 MiB document, 65536 code points / 256 KiB per final text, 500 errors, 1000 submissions, 256 dictionary entries, 2 sources. Final events after EndedAt are valid; Sources may be empty until capture metadata arrives. Segment StartedAt is rounded to seconds by UI and can slightly precede session start. All persisted/exposed times normalize to UTC.
- Clone must copy every nested slice, including submission SegmentIDs. Stores for the same absolute directory share a mutex; I/O must remain outside controller/audio locks.
- Validate with `go test -race ./internal/audiohistory`; tests use temporary directories and no providers or audio hardware.
