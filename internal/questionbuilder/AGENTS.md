# Question card state machine

- Pure bounded state under the caller's mutex; no I/O, goroutines or scheduling here. Only new system finals trigger analysis. Microphone finals provide context; system partials block automatic send. The automatic ingestion and validation share IsFiller, which preserves short meaningful replies, numbers and technical words.
- Input.Context is supplied by the controller for interpreting speech. In automatic mode Recent can also contain earlier answered questions, with bounded answer excerpts in RecentAnswers keyed by question ID. Keep chat files and answer instructions out of analysis input.
- Snapshot token invalidates late responses on edit/skip/navigation/disable; ordinary new finals remain a tail after the accepted snapshot. A saved manual version is frozen and bypasses freshness checks.
- Card owns copies of source text. Never depend on the live transcript or discard unprocessed conditions on overflow. Accepted versions persist with chat messages in the application.
- Validate model IDs against the snapshot. Automatic cards require fresh substantive system evidence, except for an explicit draft check. A continuing draft preserves its sources and may cite only its own processed evidence. An independent automatic question uses only new evidence. No-question results advance the boundary and preserve an existing card. Tests: go test ./internal/questionbuilder.
- EvidenceError marks repairable source selection and carries only static diagnostics. The Codex adapter may reconsider such a result once on the identical automatic snapshot. Validation and Apply enforce the same evidence rules on both attempts.

- Card.Origin is automatic after an accepted analysis, manual after an edit; it persists with accepted submissions. Empty origin is legacy/unknown. ValidateSources caps cumulative evidence at 80 rows / 16000 Unicode code points; reject over-budget updates before advancing processed, preserving old card and the unprocessed tail. Manual salvage remains available.

- Draft is a completed analysis result awaiting continuation or explicit review, not a running request. CanConfirm requires a nonempty fresh ready=false card with no system partial/pending final, analysis, edit, error or gap. Confirm freezes exactly that version with manual readiness semantics, without changing Origin: unedited automatic text must retain source grounding. Late speech remains a tail; no timeout may invent readiness.

- Consumed(messageID, text, ids) records a question sent directly from transcript phrases: recent gets the text (for follow-ups), processed advances to the last consumed phrase and later speech stays a tail. Manual/editing cards survive untouched; an automatic card or running analysis is invalidated.
- Refinement changes a specific previous question and requires FollowUp. A related standalone question may be a FollowUp without Refinement. Automatic follow-ups require an explicit target from Input.Recent. Sent with the same message ID updates that recent question in place. An exact repeated refinement is ignored while independently classified questions remain eligible for dispatch.
- Automatic mode may request one draft readiness check per newly analyzed draft without new system speech. BeginDraftCheck requires a fresh draft, and any accepted answer must still come from a validated model result based on that draft's sources. The check cannot rearm itself.
- Automatic analysis may return a bounded batch of ready cards after the primary card. Additional cards must have new system evidence and retain their target, refinement flag and order across Sent. Later speech waits in the transcript tail until these accepted cards are dispatched. Shared utterance IDs are allowed when one final contains multiple questions.
